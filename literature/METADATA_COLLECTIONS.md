# Metadata Collection Specification

This document is the source-of-truth description for the metadata-filtered
literature collections generated by
`literature/build_collection_metadata_sets.py` and consumed by
`literature/build_collection_metadata_synthesis_batch_input.py`.

## Purpose

These collections are an alternative to the earlier 9 A/B/C collection reports.
Instead of partitioning papers by substantive relevance switches, they group the
evidence-card corpus by metadata filters so the synthesized literature reports
can be used as prediction augmentations for:

- paper type
- citation level
- journal quartile
- publication year
- coarse discipline

The current workflow keeps all collections formed by up to 3 simultaneous
filters and drops only one-paper collections.

## Inputs

The metadata collections are built from three upstream sources:

1. `literature/output/evidence_cards/literature_evidence_cards_cleaned/combined.csv`
   This supplies the paper universe and `paper_type_primary`.

2. `paper_collection/WoS_251031_fileInfo.csv`
   This supplies:
   - `Article Title`
   - `Source Title`
   - `Publication Year`
   - `Times Cited, All Databases`
   - `ISSN`
   - `eISSN`
   - `WoS Categories`
   - `Research Areas`

3. `paper_collection/2024-2025JCRlist.xlsx`
   This supplies:
   - `Name`
   - `ISSN`
   - `EISSN`
   - `JIF`
   - `Category`

## Joins And Exclusions

- `custom_id` is normalized by stripping a trailing `.md` suffix before any
  joins.
- The evidence-card universe is left-joined to the WoS metadata on
  `custom_id`.
- JCR is matched first on `ISSN`, then on `eISSN`.
- JCR matching is not done by journal title.
- `PGG_MS_202502` is always excluded from the catalog and from every derived
  collection.

## Filter Dimensions

Collections are built over the following ordered dimensions:

1. `type`
2. `citation`
3. `jcr`
4. `year`
5. `discipline`

Only combinations of size 1, 2, or 3 are enumerated in the current run.

### 1. Type

Derived from `paper_type_primary` in `combined.csv`:

- `empirical` -> `empirical`
- `theory` -> `theoretical`

Any paper without one of those mapped values remains in the catalog but will
not appear inside collections that explicitly filter on `type`.

### 2. Citation Quartile

Citation is taken from:

- `Times Cited, All Databases`

This is intentionally not `Times Cited, WoS Core`.

Quartiles are tie-respecting and are computed from the observed citation
distribution in the catalog. The code does not use arbitrary year-style bins
and does not split identical citation counts across buckets unless the tied
value itself is chosen as a split point.

Current split upper bounds:

- `Q1_lowest`: `<= 4`
- `Q2`: `5-14`
- `Q3`: `15-44`
- `Q4_highest`: `>= 45`

Current bucket counts:

- `Q1_lowest`: `698`
- `Q2`: `681`
- `Q3`: `693`
- `Q4_highest`: `684`

### 3. JCR Quartile

JCR quartile is derived from the JCR `Category` field after ISSN/eISSN match.
The code extracts the first quartile token matching `Q1`, `Q2`, `Q3`, or `Q4`
from the raw category string.

Kept filter values:

- `Q1`
- `Q2`
- `Q3`
- `Q4`

If a paper has no JCR match, it remains in the catalog but is excluded from
collections that explicitly filter on `jcr`.

### 4. Publication Year Quartile

Publication year is taken from:

- `Publication Year`

Year buckets are also tie-respecting quartiles computed from the observed
catalog distribution.

Current split upper bounds:

- `Q1_oldest`: `<= 2012`
- `Q2`: `2013-2017`
- `Q3`: `2018-2021`
- `Q4_newest`: `>= 2022`

Current bucket counts:

- `Q1_oldest`: `705`
- `Q2`: `743`
- `Q3`: `650`
- `Q4_newest`: `658`

### 5. Coarse Discipline

`discipline_coarse` is derived from `WoS Categories` only.

Important implications:

- This is journal-dependent metadata in the current WoS export.
- The discipline field is multi-label.
- A paper can therefore belong to more than one discipline collection.
- Discipline-filtered collections are not mutually exclusive.

The label assignment heuristic is:

- `multidisciplinary`
  Only when a WoS category equals exactly `Multidisciplinary Sciences`.
  This is intentionally narrow so categories like
  `Psychology, Multidisciplinary` are not treated as Nature/Science/PNAS-style
  multidisciplinary journals.

- `economics`
  Assigned when a category contains `economics` or equals `business, finance`.

- `psych_social`
  Assigned when a category contains any of:
  - `psychology`
  - `behavioral sciences`
  - `sociology`
  - `social sciences`
  - `management`
  - `business`
  - `anthropology`
  - `political science`
  - `international relations`
  - `ethics`
  - `development studies`
  - `area studies`

- `bio_evo`
  Assigned when a category contains any of:
  - `biology`
  - `ecology`
  - `evolutionary`
  - `neurosciences`
  - `genetics`
  - `zoology`
  - `ornithology`
  - `biodiversity conservation`

- `math_phys_cs`
  Assigned when a category contains any of:
  - `physics`
  - `mathematics`
  - `mathematical`
  - `statistics`
  - `computer science`
  - `automation & control systems`
  - `operations research`

- `other`
  Assigned only if no labels above are matched.

Notes:

- `complex systems` is intentionally not used as a `math_phys_cs` trigger.
- `Psychology, Multidisciplinary` is classified as `psych_social`, not
  `multidisciplinary`.
- Because the field is multi-label, a paper can be classified as, for example,
  `economics;psych_social`.

## Collection Enumeration Rule

The collection builder enumerates:

- every 1-way combination of the 5 dimensions
- every 2-way combination of the 5 dimensions
- every 3-way combination of the 5 dimensions

For each dimension combination, it enumerates the full Cartesian product of
that dimension's allowed values and keeps the combination if:

1. at least one paper matches
2. the number of matching papers is at least `min_papers`

Current run parameters:

- `max_filters = 3`
- `min_papers = 2`

This means the current run drops only one-paper collections.

## Naming Convention

Collection ids are deterministic slugs built from the active filter values, in
the fixed dimension order:

- `citation_q1_lowest`
- `type_empirical__jcr_q2`
- `citation_q4_highest__year_q3__discipline_economics`

The human-readable version of the same filters is stored as `filter_label` in
the summary CSV, for example:

- `citation=Q4_highest | year=Q3 | discipline=economics`

## Output Files

The collection builder writes:

- `literature/output/evidence_cards/literature_evidence_cards_cleaned/collection_metadata_sets/collection_metadata_catalog.csv`
  Enriched paper-level catalog with all derived metadata columns.

- `literature/output/evidence_cards/literature_evidence_cards_cleaned/collection_metadata_sets/collection_metadata_summary.csv`
  One row per retained collection.

- `literature/output/evidence_cards/literature_evidence_cards_cleaned/collection_metadata_sets/collection_metadata_summary.json`
  Run-level metadata and counts.

- `literature/output/evidence_cards/literature_evidence_cards_cleaned/collection_metadata_sets/sets/*.csv`
  One `custom_id` list per retained collection.

## Synthesis Prompt Generation

`literature/build_collection_metadata_synthesis_batch_input.py` consumes the
retained collection summary and emits:

- one digest bundle `.md` per collection in
  `literature/output/collection_metadata_synthesis_inputs/`
- one synthesis request per collection in
  `openAI_batch_input/synthesis_collection_metadata_filters.jsonl`

Prompt-format notes:

- The prompt does not include collection ids or applied-filter metadata inside
  the request body.
- The digest header keeps only:
  - `# Paper Set Evidence Digest`
  - `Number of papers in this paper set: N`
  - `Each item below is a compact paper-level analysis digest. Use only this digest.`

## Downstream Prediction Augmentation

After the synthesis outputs are available in
`openAI_batch_output/synthesis_collection_metadata_filters.jsonl`,
`literature/build_prediction_batch_from_collection_reports.py` can be used to
build model-specific prediction batch files that wrap each synthesized metadata
collection report as augmentation context.

One shared CLI quirk: `build_prediction_batch_from_collection_reports.py` still
accepts a `--leaf-legend-csv` argument because it is shared with the older
switch-set workflow. For metadata collections that file is unused and may point
to a nonexistent path.

The current generated augmentation files are:

- `prediction_literature_collection_analysis_report_metadata_filters_joint_reps1to5_41.jsonl`
- `prediction_literature_collection_analysis_report_metadata_filters_joint_reps1to5_41mini.jsonl`
- `prediction_literature_collection_analysis_report_metadata_filters_joint_reps1to5_gpt51.jsonl`
- `prediction_literature_collection_analysis_report_metadata_filters_joint_reps1to5_gpt5mini.jsonl`
- `prediction_literature_collection_analysis_report_metadata_filters_joint_reps1to5_gpt5nano.jsonl`

Each of those files contains:

- `716` collection reports
- `5` repetitions per collection
- `3580` requests total

## Regeneration Commands

Rebuild the metadata collections:

```bash
python literature/build_collection_metadata_sets.py
```

Rebuild the metadata-collection synthesis input:

```bash
python literature/build_collection_metadata_synthesis_batch_input.py
```

Rebuild the metadata-collection prediction augmentations:

```bash
python literature/build_prediction_batch_from_collection_reports.py \
  --report-output-jsonl openAI_batch_output/synthesis_collection_metadata_filters.jsonl \
  --leaf-legend-csv literature/output/collection_metadata_synthesis_inputs/leaf_legend.csv \
  --direct-manifest-csv literature/output/collection_metadata_synthesis_inputs/request_manifest.csv \
  --report-root literature/output/collection_analysis_reports/metadata_filters \
  --models gpt-4.1-2025-04-14 gpt-4.1-mini-2025-04-14 gpt-5.1 gpt-5-mini gpt-5-nano \
  --n-explanation-repeats 5 \
  --output-prefix prediction_literature_collection_analysis_report_metadata_filters_joint_reps1to5
```
